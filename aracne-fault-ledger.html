What this is

go vet ./... is clean and the existing suites are thorough, so none of these are crashes or type errors. Each is a place where the code does something its own doc comment says it does not — a parser documented as pure that mutates its input, a validator documented as loud that cannot fire, a manifest that records a state it never observed.

Withdrawn

A first pass produced 57 candidates. 43 are gone. Recording why matters as much as the list that survived: most were not defects, they were decisions I had not yet found the reasoning for.

Withdrawn because a comment in the code defends the behaviour

  • grep over a directory without -r. Modelled as recursive where GNU grep says "Is a directory". parseGrep states it: "Accepted and ignored: aracne always reports path:line, and always recurses into a directory operand." A deliberate divergence, not an oversight.
  • shellcmd.Base lowercasing the command word. Documented: "so /usr/bin/sed, \sed and SED.EXE all resolve to sed." The PowerShell surface needs it.
  • wrappedCommandIndex promoting an argument into the command slot. The function exists to do that (rtk proxy sed …), and its comment accepts the false positives the bound still allows.
  • splitCommandSegments not handling backslash escapes. Declared "a pragmatic tokenizer, not a real shell parser", with residual false positives accepted.
  • idresolve preferring the shortest matching ID. Argued for explicitly: "a caller who wrote a.b.Foo almost always meant the former."
  • head/tail group headers replacing ==> f <==. Stated in serveRead: "the group header above each block carries the filename that head's own banner would have."
  • lazydesc discarding results that arrive after the deadline. Both halves are documented intent — the timeout ("so the read returns on time") and the permanent claim ("whether or not the attempt succeeds").
  • proxyRead resolving its target against the hook's cwd. The function states that returning "" whenever it cannot be certain is the designed outcome.
  • Dangling incoming edges after a scoped delete. WriteDelta says they are kept on purpose: "they drive missing-node warnings."

Withdrawn because the reproducer did not reproduce

  • Scanner errors persisted as warnings with an empty Kind. I wrote the probe: an unparseable Go file put through IncrementalScan produced err=nil, zero returned warnings and zero stored warnings. The "error:"+path branch in manager.go is not reached by a syntax error, so the claim was wrong.

Withdrawn as not confirmed

  • Guard timeout budget. 20s + 5s + 3s under a 30s hook timeout is tight, but I could not show the stages actually serialising in one call, so the arithmetic is not evidence.
  • update-file --claude-hook writing bare text to stdout. Whether that reaches the model depends on the host's hook contract, which I did not verify.
  • OpenCode setup deleting the write permission key. Plausibly deliberate normalisation — aracne folds writes into edit — rather than destruction.
  • The partial fast path not clearing use_missing_node warnings. I could not build a reproducer I trusted to be exercising the fast path rather than something else.
  • viz: optimization_rules as a write target, a GET with a side effect, an absent Origin treated as trusted, no Sec-WebSocket-Version check. Each is a defensible posture for a loopback developer tool; none is provably wrong.

Withdrawn as true but not bugs

  • Style and hygiene: regexpQuote duplicating regexp.QuoteMeta; an unused root parameter on normalizeManifestPath; a cfg != nil check on a value that is never nil; RunRead reading os.Args instead of its argument; five duplicated comment lines in viz/server.go.
  • Performance: DetectAll walking the tree twice per incremental scan; idresolve tokenising the whole graph per lookup; countFileLines converting a file to a string twice.
  • Documentation drift (worth fixing, but not faults): docs/architecture.md §9 still describes the pre-segment-splicing interception rule, so two of its six named guard rails no longer hold; and EffectiveMode's comment promises a legacy integration.mode fallback tier that does not exist in the code.
  • Design properties: absolute paths in the database and manifest making the store non-relocatable; SaveConfig not using AtomicWriteFile; timeouts that stop the wait without stopping the work. Real, but each is a trade rather than a mistake, and none is demonstrable as a failure.

Excluded by request

  • Everything in internal/chat and its permission policy.

Checked and found sound

Worth recording so a later pass does not re-tread it: the all-or-nothing batching and CRLF matching in llm/tools/edit.go; helper.AtomicWriteFile as a correct atomic replace; topogrep's context map, binary-file handling and per-file -m cap; domain.GlobToRegexp's zero-directory **/ case; the raw-JSON id handling and notification/ping dispatch in internal/mcp; and the loopback-host check that does defeat DNS rebinding on the viz API's mutating routes.
